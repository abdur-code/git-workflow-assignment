    Moves into the project folder so all commands run inside it.

    (creates the hidden .git directory) with "main" as the default branch.

    Sets the author name and email recorded in every commit
    for this repository.

git status

---------------------------------------------------------------------
STEP 2: GIT WORKFLOW EXECUTION
---------------------------------------------------------------------
git add index.html about.html
    Stages the two HTML files so they are included in the next commit.

git commit -m "Initial commit: add index.html and about.html"
    Records the staged files as the first snapshot (initial state)
    of the project, with a descriptive message.

git diff
    Shows line-by-line changes in the working directory that are not
    yet staged (used to review the edits to index.html / about.html).

git add index.html
git commit -m "Update index.html: add navigation bar and footer"
    Stages the modified index.html and records it as the second commit.

git branch feature
    Creates a new branch named "feature" pointing at the current commit.

git branch
    Lists all local branches; the current branch is marked with "*".

git checkout feature
    Switches the working directory to the "feature" branch.
    (Equivalent modern command: git switch feature)

git add about.html
git commit -m "Feature: add skills section and navigation to about.html"
    Stages and commits the about.html changes on the feature branch only.

git log --oneline
    Shows a compact history: one line per commit (short hash + message).

git checkout main
    Switches back to the main branch (the feature change is not visible here yet).

git merge --no-ff feature -m "Merge branch 'feature' into main"
    Merges the feature branch into main. --no-ff forces a merge commit
    so the branch activity remains clearly visible in the history.

git log --oneline --graph --all --decorate
    Displays the full commit history of all branches as an ASCII graph,
    showing where the feature branch split off and was merged back.

git log --stat
    Shows the detailed history with author, date, message and the
    files/lines changed in each commit.

STEP 3: .gitignore IMPLEMENTATION
---------------------------------------------------------------------
cat .gitignore
    Displays the .gitignore rules: "*.log" (all log files) and
    "temp/" (the temp folder).

echo "debug output" > debug.log
mkdir temp && echo "scratch notes" > temp/notes.txt
    Creates a log file and a temp folder to test that they get ignored.

git check-ignore -v debug.log temp/notes.txt
    Confirms which .gitignore rule (file and line) ignores each path.

git add .gitignore
git commit -m "Add .gitignore to ignore .log files and temp/ folder"
    Stages and commits the .gitignore file so the rules are shared.

git status --ignored
    Shows the working tree status including ignored files, proving
    debug.log and temp/ are ignored and not tracked.

---------------------------------------------------------------------
STEP 4: UNDO OPERATION
---------------------------------------------------------------------
git add contact.html
git commit -m "Add contact.html page"
    Makes an additional commit (adds contact.html) that will be undone.

git log --oneline -3
    Shows the last 3 commits to confirm the new commit is at the top.

git revert HEAD --no-edit
    Undoes the last commit by creating a new commit that reverses its
    changes (contact.html is removed). History is preserved, so this is
    the safe undo for commits that are (or will be) pushed/shared.
    --no-edit accepts the default "Revert ..." commit message.
    (Alternative for local-only commits: git reset --soft HEAD~1 removes
    the commit but keeps its changes staged; git reset --hard HEAD~1
    removes the commit and discards the changes.)

git show --stat HEAD
    Shows details of the latest (revert) commit and the files it changed.

ls
    Lists files to show contact.html no longer exists after the revert.

STEP 5: GITHUB INTEGRATION
---------------------------------------------------------------------
(GitHub web UI) github.com/new -> name "git-workflow-assignment" -> Public
    Created a new, empty PUBLIC repository on my personal GitHub account
    (abdur-code), without a README/.gitignore/license so the local history
    can be pushed as-is.

ssh -T git@github-personal
    Verifies that the SSH key for my personal account authenticates with
    GitHub ("github-personal" is a Host alias in ~/.ssh/config pointing to
    github.com with my personal SSH key).

git remote add origin git@github-personal:abdur-code/git-workflow-assignment.git
    Connects the local repository to the GitHub repository under the
    name "origin", over SSH using the personal-account key.

git remote -v
    Lists the configured remotes and their fetch/push URLs.

git push -u origin main
    Uploads the main branch and its full history to GitHub; -u sets
    origin/main as the upstream so later "git push" needs no arguments.

git push origin feature
    Pushes the feature branch too, so branch activity is visible on GitHub.

git branch -a
    Lists local and remote-tracking branches (confirms origin/main and
    origin/feature exist).
